# kankan destroy — technical specification

**Status:** implemented locally; live check on a disposable board passed 2026-11-21; final review fixes (2026-11-21) implemented locally, not yet re-run live.
**Date:** 2026-11-20
**Base:** [`initial_spec_technical.md`](initial_spec_technical.md) v1.3 and [`stopall_spec_technical.md`](stopall_spec_technical.md); this feature changes them as listed in [§9](#9-changes-to-the-initial-technical-specification).
**Companion:** [`destroy_spec_functional.md`](destroy_spec_functional.md) — the behaviour this file implements; read it first.

**Split rule.** The functional file describes what users observe; this file describes how kankan implements it. Section numbers are this feature's own.

## 1. Scope

New module `kankan/destroy.py`, called by the new `destroy` command in `cli`. It reuses `stopall.sessions` (made public) and a new `seats.running` for the gate, `refstore` for the refs (the only module touching `refs/agent-*`: the deletion transaction is `RefStore.delete_exact`), `trello.TrelloClient` for the board and `init.hook_path`/`init.hook_content` for the hook. Two Trello reads are added ([§6](#6-trello-usage)); `kanban_requirements.md` changes with them.

## 2. Gate

`stopall.inventory(project, tmux)`: any seat `alive` or `unavailable`, any session of the project or an installed autostart unit (`agents_cmd.unit_path(project).exists()`) → `KankanError(NEEDS_ACTION)` listing them with "run `kankan stop` first". The gate runs once before the questions (fast refusal) and again under the project lock, right before destruction ([§4](#4-sequence)).

The seats checked are the union of `cfg.seats`, the `refs/agent-seats/*` refs and the seat names of `<gcd>/kankan/seats/*` files, so a seat missing from the configuration is not overlooked. A seat is running when its liveness lock (`seats/<seat>.lock`) cannot be taken non-blocking, or when a process recorded in its `<seat>.proc.json` is still alive with the same boot ID and start time (the check `seats` already performs for `unavailable`), whether or not a seat ref exists. The probes never create files: a missing lock file means that lock is not held. The remedy is `kankan stop` only for a seat of the configuration when the project can be opened (`kankan stop` knows only those seats). Otherwise — no usable configuration (`load_config` fails or has no board), or a seat found only through its refs or files — the remedies are the underlying commands, since `kankan stop`, `seat recover` and `autostart disable` open the project: `kill <pid>` for each live recorded process, the lock-holder command (`fuser <lock>`) for a held liveness lock, `tmux kill-session -t <name>`, `systemctl --user disable --now <unit>` and `rm <unit path>`.

**Files opened.** Before the gate (and again under the project lock) `destroy` checks without following links that `<gcd>/kankan` and `<gcd>/kankan/seats` are absent or real directories, and that `project.lock`, each known seat's `<seat>.lock` and `<seat>.proc.json` and `log.jsonl` are absent or regular files (`log.jsonl` with one link): the gate opens the seat files, the lock is opened after the questions. `Ctx.open` makes the root check before `try_load`, so a `config.json` behind a linked root is never read (the context records the reason; `destroy` and `local_plan` raise it). The project lock is taken with `project_lock(paths, nofollow=True)`: `<gcd>/kankan` is opened with `O_DIRECTORY | O_NOFOLLOW` and `project.lock` relative to that descriptor with `O_NOFOLLOW | O_NONBLOCK`, and anything but a regular file raises before a file is created; `auditlog.append(follow=False)` opens `log.jsonl` the same way. An `OSError` taking the lock is `NEEDS_ACTION` with the `rm` command.

## 3. Inventory

`plan(project) -> Plan`, read-only:

- **Board** (only with a configuration whose board can be read and whose `registry-id` matches `cfg.registry_id`, or whose description has no registry block at all: an interrupted `destroy` removed it, and another clone would have written its own): the snapshot (`TrelloClient.snapshot`, which carries the board name and description); the **target lists** are `cfg.backlog`, `cfg.done`, `cfg.blocked`, `cfg.qa_list`, `cfg.settings_list` and the three lists of every work seat in `cfg.seats`, each only if set; the **cards** are the open cards of the snapshot whose `idList` is a target list, plus the archived ones read with [§6](#6-trello-usage); the **seat lists** to archive are the seat lists not already closed; the **labels** are the board labels whose name parses as `labels.RESUME_PREFIX` + `%Y-%m-%d %H:%M` with the parser `labels` already uses, minus those carried by a card (open or archived) outside the target lists, which are reported as kept; `config.registry_state(desc)` (new) tells whether the block is absent, valid (exactly one complete block with exactly one non-empty `registry-id` line) or malformed; malformed raises `NEEDS_ACTION` before any question. Kept lists and target cards are keyed by list ID, the name being only for display. A mismatching `registry-id`, an unreadable board (401, 403, 404) or a configuration without a board set `board = None` with the reason, used for the phrase `remove local kankan state` and the report (for an unreadable board, the manual cleaning note of [functional §5](destroy_spec_functional.md#5-errors)). Any other `TrelloError` (timeout, 429, 5xx) raises `NEEDS_ACTION` before any question. The current names of the kept lists are recorded for the report.
- **Worktree root:** `paths.worktree_root` and `<gcd>/kankan` must be disjoint, compared with `os.path.commonpath` both as written (`abspath`) and with links resolved (`realpath`): one inside the other, or equal, raises `NEEDS_ACTION` before git runs in any worktree and before any question, since the state sweep removes everything under `<gcd>/kankan` and the worktree inventory would list the state directory as a kept entry. A root that is an ancestor of `<gcd>` (for example the folder holding the main checkout, with seat worktrees beside it) is refused too. Likewise any worktree registered by git (`git worktree list`, the main one excepted) whose path, as written or resolved, is inside `<gcd>/kankan` is refused whatever the root: otherwise pointing `worktree_root` elsewhere would turn it into plain state that the sweep deletes without the discard question. The message says to move worktrees and the user's files out of `<gcd>/kankan` first (`git worktree move`, `mv`).
- **Worktrees:** the entries of `worktrees.worktree_list(repo)` whose path is exactly `paths.worktree_root / <seat>` for a seat found by the gate ([§2](#2-gate)) or `paths.worktree_root / blocked-<shortLink>` with a valid shortLink; the main worktree never. Every other entry or directory under the root is reported as kept and never touched. For each target: its branch or detached HEAD; `git status --porcelain=v1 --untracked-files=all` (ignored files excluded) for uncommitted changes; `MERGE_HEAD`, `rebase-merge`/`rebase-apply` and `CHERRY_PICK_HEAD` in the worktree's git dir for an operation in progress; on a detached HEAD, `git rev-list HEAD --not --branches --remotes` for unreachable commits; `git status --porcelain=v1 --ignored` for the count and first examples of ignored files. A target registered but whose directory is gone is inspected in its administrative directory `<gcd>/worktrees/<id>`: `HEAD` (a branch, or a commit checked for unreachable commits as above), the operation markers, the `index` and `modules/`. The index is compared with the recorded HEAD by `git -c core.fsmonitor=false --no-optional-locks diff-index --cached --no-renames --name-only -z <HEAD>` with `GIT_INDEX_FILE` set to it (read only: `--cached` refreshes nothing and the optional locks are off); for an unborn branch every entry of `ls-files --cached` counts. The differing entries are staged work at risk. No index file means nothing staged; an index that is not a regular file, or that git cannot read, raises `NEEDS_ACTION`. A `modules/` that is anything but an empty directory is submodule storage at risk; one that cannot be listed raises `NEEDS_ACTION`.
- **Interrupted blocks:** seat state files whose `block_journal` is set (the journal is written before the snapshot exists), and the directories under `<gcd>/kankan/blocks/` (named by shortLink only; one without a journal has no known seat, so only its path and files are shown); each snapshot is listed through directory descriptors: the snapshot directory, its `files` entry and every directory below are opened with `O_DIRECTORY | O_NOFOLLOW` relative to their parent's descriptor and read with `os.scandir(fd)`, so a link swapped in after a check is never followed; a `files` entry that is a symbolic link is shown as `<symlink: files not listed>` and removed as a link, and links inside it are listed as entries, never descended; each is work at risk, reported with the seat to start ([functional §3](destroy_spec_functional.md#3-kankan-destroy---confirm-phrase)).
- **Refs:** `refstore.list_raw` of `refs/agent-cards/` and `refs/agent-seats/`, plus `git for-each-ref --format='%(refname) %(symref)'` on both prefixes: a symbolic agent ref raises `NEEDS_ACTION` before any question.
- **Hook:** `init.hook_path(paths)`; kankan's only when its content equals `init.hook_content()` and the hook is the repository's own: its directory, links resolved, is inside `<gcd>` or the main checkout, and either no `core.hooksPath` is set (`git config --get` exits 1, the default `<gcd>/hooks`) or the value git uses equals the one in the repository's own configuration file (`git config --file <gcd>/config --get core.hooksPath`, `GIT_CONFIG` removed). kankan's exact hook elsewhere (a global or system `core.hooksPath`, an include, a `<gcd>/hooks` linked to a shared directory) is `shared`: kept and reported, never removed, since other repositories use it. Anything else (another hook, a kankan hook modified or from another kankan version) is `foreign`, kept and reported. `_git_step` checks content and ownership again before unlinking.
- **Git configuration:** `git config --local --get kankan.integrationBranch`.
- **Integration branch:** `cfg.integration_branch` (or the git configuration entry without a configuration), with `refs/heads/<name>` checked through `git rev-parse --verify` and the remote through `git -c credential.helper= ls-remote origin refs/heads/<name>` with `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=/bin/false`, `SSH_ASKPASS=/bin/false` and `GIT_SSH_COMMAND` set to the user's `GIT_SSH_COMMAND` or `core.sshCommand` (else `ssh`) followed by `-o BatchMode=yes`, so no credential helper runs (none can store or erase a credential) and nothing prompts, comparing the full ref name returned (any failure, a remote asking for credentials included, gives `unknown`, never an error); for a branch only on `origin`, the rename commands fetch its tip first (`git fetch origin refs/heads/<name>`, then `git push origin FETCH_HEAD:refs/heads/<name>-old`); when the kept hook is not kankan's exact one, the commands note that the hook may refuse the push; `cfg.user_branch` to suppress the rename and delete commands when they are equal; read only, never changed. It feeds the warning and the commands of [functional §3](destroy_spec_functional.md#3-kankan-destroy---confirm-phrase) step 7.
- **Exclude:** the two consecutive lines `# kankan` and `/.kankan/` written by `init.add_excludes` in `<gcd>/info/exclude`; a `/.kankan/` line without them is the user's.
- **State:** the entries of `<gcd>/kankan/`, except kankan's lock files: `*.lock` directly in `<gcd>/kankan/`, in `seats/` and in `attachment-locks/`, and `qa/<conversation>/op.lock`. Other files, whatever their name (a downloaded `yarn.lock` under `attachments/`), are state.

`Plan.empty` is true when every part is empty (kept items, such as a foreign hook, lock files or user worktrees, do not count) and the board is `None` or has nothing to do; the command then returns `nothing_to_destroy` without asking.

## 4. Sequence

1. Gate ([§2](#2-gate)); inventory ([§3](#3-inventory)); print it (`describe(plan)`).
2. Work at risk (uncommitted changes, operations in progress, unreachable commits, interrupted blocks): print, per finding, the files or commits and the commands of [functional §3](destroy_spec_functional.md#3-kankan-destroy---confirm-phrase); `ask(DISCARD_PHRASE)` where `DISCARD_PHRASE = "discard uncommitted work"`.
3. `ask(expected)` with `expected = f"destroy {board.name}"` or `LOCAL_PHRASE = "remove local kankan state"`; the board name is the one read in step 1, never printed.
4. Under `config.project_lock(paths, nofollow=True)` ([§2](#2-gate)): the state files are checked again; the configuration is loaded again (`Ctx.open`) and must match the one the inventory used — board and registry IDs (or no configuration, with the same reason), the paths (`repo`, `gcd`, `kankan_dir`, project name, worktree root), the integration branch name, the target lists of [§3](#3-inventory) and the seats `known_seats` finds — else `NEEDS_ACTION` before any write, local-only runs included (a configuration `init` wrote during the questions stops the run); the agent refs must be exactly those inventoried (names and values) with no symbolic one; and the interrupted blocks must be exactly those shown, compared by identity (journal seat, short link, snapshot path, file list, link flag) whether or not `discard uncommitted work` was typed: a new or changed snapshot or journal stops the run, since the discard covered only the work shown. Then the gate again with the fresh context, then the board name and `registry-id` are re-read with the snapshot; the board is inventoried again and a different name or binding (renamed or rebound meanwhile), a card added to or moved between kankan's lists, a new `Resume` label or a reopened seat list cancels with `needs_action` asking to run `destroy` again. The worktrees are inventoried again too: a target added or removed, or work at risk in a target outside the confirmed discard set (the targets at risk at step 2 when it was accepted, empty otherwise), cancels the same way before the first board write; targets in that set may have changed, since the user agreed to discard their work, and keep `--force`. Then:
   1. **Board:** for every card, `card_place` (`GET /1/cards/{id}?fields=idList,closed`) right before `delete_card`: a 404 counts as done (and no delete is sent), a card whose `idList` is no longer a target list is skipped (`cards_skipped`), a malformed answer stops; `archive_list` for every seat list; then the board is read again (`board_plan`) and each `Resume` label that is no longer deletable (a card outside the target lists carries it now, or it is gone) is kept (`labels_kept`), the others are deleted with `delete_label` (404 as done); then the board is read again (`board_plan`): a card in a target list (open or archived: it arrived during the run) stops with `NEEDS_ACTION` before the registry block and every local step, so the configuration that finds it survives; a board no longer this clone's stops the same way; otherwise, when this read shows the block, `set_board_desc` with the registry block removed from this read's description (`config.remove_registry_block`, new, the inverse of `write_registry_block`, keeping the rest byte for byte except the newlines that separated the block: a description that ended with a newline before the block comes back without it), skipped when the block is already absent. Any other `TrelloError` stops here with `NEEDS_ACTION` and the report of what was done. Residual windows: Trello has no conditional delete, so a card moved out of kankan's lists between its `card_place` read and its `DELETE` (one request apart), a label that gains an outside card between the label re-read and its `DELETE`, a card arriving between the last board read and the `PUT` of the description, and a description edit in that same interval (overwritten by the description read just before) are not detected; each window is a few requests long instead of the whole batch.
   2. **Worktrees:** each target is inspected again right before its removal (`_reinspect`); work at risk found then in a target outside the confirmed discard set stops the run, and otherwise git's own check (no `--force`) refuses a worktree that turned dirty in between; `git worktree remove --force <path>` for each target of [§3](#3-inventory) (with work at risk only when step 2 was accepted), then `rmdir` of `paths.worktree_root` when empty. No repository-wide `git worktree prune`: a target registered but whose directory is gone is unregistered by removing its own administrative directory under `<gcd>/worktrees/` (the one whose `gitdir` file points at it), so other stale registrations are untouched. A failure stops with `NEEDS_ACTION` before the refs.
   3. **Refs:** `RefStore.delete_exact(refs)`: one `git update-ref --no-deref --stdin` transaction deleting every `refs/agent-cards/*` and `refs/agent-seats/*` ref with its inventoried value as the expected old value; a ref changed during the questions already stopped the run under the lock; one that changed during the board or worktree steps stops the run here with `NEEDS_ACTION` ("run `kankan destroy` again"), since the inventory the user confirmed is stale.
   4. **Hook:** removed only when kankan's ([§3](#3-inventory)). **Git configuration:** `git config --local --unset kankan.integrationBranch` (exit code 5, "not set", is done). **Exclude:** the two-line kankan block removed, the file rewritten atomically, other lines untouched.
   5. **State, last:** every state entry of [§3](#3-inventory), recursively (attachments, blocks, Q&A records and conversations, seat state, board settings state, `log.jsonl`, `stopped.json`, `agents.json`), keeping kankan's lock files and the directories that hold them, and `config.json` removed after everything else; the lock files stay because locks are never deleted (initial T§5.2). Before the removal a `destroy` event with the plan's counts is appended to `log.jsonl` (`auditlog.append`, which creates the file if needed), and `log.jsonl` is then removed with the rest, whether or not it was in the inventory; the same summary is printed.
5. Report data: `{"board": {"url", "cards_deleted": {list name: n}, "cards_skipped": n, "lists_archived": [name…], "labels_deleted": [name…], "labels_kept": [name…], "registry_removed": bool} | null, "board_skipped": reason | null, "worktrees_removed": [path…], "refs_deleted": n, "hook": "removed" | "foreign, kept" | "shared, kept" | "absent", "git_config": bool, "exclude": bool, "state_removed": bool, "kept": [text…], "kept_lists": [{"id", "name"}…], "manual_board_cleanup": reason | null, "integration_branch": {"name", "local": bool, "origin": true | false | "unknown", "is_user_branch": bool, "commands": [text…]} | null, "next": "kankan init <board-url>"}`, plus `nothing_to_destroy` or `cancelled` when they apply.

The project lock is not held while asking: a user typing slowly does not block other commands, and step 4 re-checks everything the answers depended on.

## 5. Questions and `--confirm`

`destroy(project, *, ask: Callable[[str], Optional[str]], say, confirm: List[str])`: `ask(prompt)` returns the line typed or `None` for Ctrl-C/EOF. The CLI implements it with `input()` (prompt on stderr), mapping `KeyboardInterrupt` and `EOFError` to `None`. For each question, a `--confirm` value equal to the expected phrase answers it without asking. Without a terminal (`not sys.stdin.isatty()`) the CLI passes an `ask` that raises `KankanError(USAGE_ERROR)` naming the missing phrase; a `--confirm` value that matches no question asked (a wrong board name, or `discard uncommitted work` when nothing is at risk) is a `usage_error` too, raised after the read-only inventory and before any write; the error never prints the expected board name. The answer is compared after `strip()`, exactly. An argument error while parsing a command line that holds `destroy` (e.g. an unquoted `--confirm destroy My Board`) is a `usage_error` with the fixed `messages.DESTROY_USAGE`, in text and JSON: argparse's own message would repeat the arguments, and so the board name.

## 6. Trello usage

- **Archived cards of the target lists:** `GET /1/boards/{id}/cards/closed?fields=idList,name,idLabels` filtered on `idList` (new `TrelloClient.closed_cards(board_id)`), read in ONE request with `limit=1000`, never paged; two rows with one ID are compared before deduplicating: identical rows count once, rows differing in `idList` or `idLabels` raise `TRELLO_ERROR` with `{"conflict": true}` (`board_plan`: the board-changed `NEEDS_ACTION` before any question); paging with `before=<id>` loses cards on the live service (observed 2026-11-21 on three archived cards A<B<C: `limit=1` gives [C], `limit=1, before=C` gives [A], `limit=2, before=C` gives [A] and skips B). A response of `limit` rows or more (a full page, so there may be more) raises `NEEDS_ACTION` with the too-many-archived-cards message (1000 or more: delete or restore some in Trello and run again), before any question and any write; a row without `idList` raises `TRELLO_ERROR`. The snapshot only carries open cards. A failed or incomplete read stops before the first delete.
- **One card's place:** `GET /1/cards/{id}?fields=idList,closed` (new `TrelloClient.card_place`, C1 with other fields) right before each card deletion; 404 → gone.
- **Existing calls with a new use:** `DELETE /1/cards/{id}` (`delete_card`), `PUT /1/lists/{id}/closed` (`archive_list`), `DELETE /1/labels/{id}` (`delete_label`), `PUT /1/boards/{id}` `desc` (`set_board_desc`).
- Deletions go through the client's rate limiter; at Trello's limit (about 100 requests per 10 seconds) a board with hundreds of cards takes tens of seconds, and progress is printed every 25 cards.

`kanban_requirements.md`: B3 (the board name is used by `destroy`, and the board is read again during destruction), C1 (`fields=idList,closed` before each delete), C6 (deletion used by `destroy`, no longer only by the live tests), L2 (archive of seat lists by `destroy`), T2 (deletion of `Resume` labels by `destroy`), B2 (removal of the block), and row C10 for reading a board's archived cards (`GET /1/boards/{id}/cards/closed`; SHOULD: without it, archived cards stay in Trello's archive; contradictory rows refuse).

## 7. Changes to existing code

- `cli`: new command `destroy` with repeatable `--confirm` (`action="append"`); like `start`, it does not require a loadable configuration ([§3](#3-inventory)).
- `config`: `remove_registry_block(desc) -> str`; `registry_state(desc)` (absent, valid — exactly one `registry-id` line, non-empty — or malformed); `try_load(cwd)`, which returns the paths, the configuration and the reason it could not be loaded, and never raises on a missing, non-object or malformed `config.json`; it also validates every list ID destroy uses (`backlog`, `done`, `blocked`, `qa_list`, `settings_list`, and each seat's `in_progress`, `implemented`, `review` and `role`: a string or absent/null; `seats` a mapping of mappings), an invalid one making the configuration unusable with its reason; `file_lock`/`project_lock` take `nofollow` and `open_nofollow(path, flags)` opens a file relative to its verified directory ([§2](#2-gate)).
- `trello`: `closed_cards(board_id)`, `card_place(card_id)` and `board_payload(board_id)` (the raw board read that `destroy` validates strictly); `delete_card` treats 404 as done, as `delete_label` does.
- `refstore`: `delete_exact(refs)` (expected-OID, `--no-deref` deletion of agent refs; any name under the two agent prefixes).
- `cli`: an argument error for `destroy` prints `messages.DESTROY_USAGE` instead of argparse's message.
- `seats`: `running(paths, seat)`; `stopall`: `sessions` public; `labels`: `resume_time` public and strict (literal prefix, zero-padded `YYYY-MM-DD hh:mm`, re-formatted equal to the input).
- `gitutil`: `run_bytes` (git output as bytes, for paths and names that are not UTF-8).
- `auditlog`: `append(..., follow=False)` opens `log.jsonl` relative to `<gcd>/kankan` opened with `O_DIRECTORY | O_NOFOLLOW` (neither is followed), refuses anything but a regular file with one link and never blocks on a FIFO.
- `messages`: the texts of the questions, the uncommitted-work commands, the report and the refusals.
- User manual: `destroy` is described in section 12.3, "Starting over: kankan destroy", and in the command reference.
- `kanban_requirements.md` is revised in the implementation commit as listed in [§6](#6-trello-usage).

## 8. Tests

Unit tests with the existing fake Trello client and temporary git repositories, one per acceptance test of [functional §7](destroy_spec_functional.md#7-acceptance-tests), plus: the interruption tests inject a failure into `delete_card`, right after `set_board_desc` and into `git worktree remove`, and check that `config.json` survives and the second run finishes; the name check uses a fake board whose URL slug differs from its name; the race test renames the board between the question and the lock; a custom worktree root holds a user worktree that survives; a ref changed after the inventory stops the run; a full page of archived cards refuses before any question and write. The final review added (`tests/test_destroy_final.py`): an overlapping worktree root with a sentinel; a missing checkout with a staged file, with submodule storage, with an unreadable index or `modules/`; a seat, a configuration, a list, a ref or a snapshot appearing while the questions are open; a card moved out, a card added and a `Resume` label gaining an outside card during the deletion; two `registry-id` lines; contradictory archived rows; a kankan hook in a global `core.hooksPath`; linked state root, `seats/`, `project.lock`, seat files and `blocks/*/files`; a `project.lock` link swapped in during the questions; the remote probe against an HTTP remote asking for credentials, with a helper that would write a sentinel; `destroy --confirm destroy Sample Board` in text and JSON; invalid list IDs.

A live check (`tests/live/`) runs on a **disposable board** created for the test, never on the shared test board: it seeds kankan's lists with a card carrying an upload, a link, a comment and a checklist, an archived card, a card in a list kankan does not know and a `Resume` label, runs `destroy`, checks what is gone and what remains, runs `init` and checks the adoption by name.

## 10. Accepted limitations

The final review left these cases open. They need an unusual setup or someone changing things while the questions are open, and they are accepted as they are:

- the configuration's `trello_base_url` changed during the questions: the final board check uses the new server;
- a registry block written to the board description during the run, when there was none at confirmation, is removed;
- an unknown seat role in the configuration counts that seat's lists as seat lists;
- a `Resume` label is not read again right before its deletion;
- a worktree whose directory is gone is treated as unborn when its branch cannot be read;
- the overlap between the worktree root and `<gcd>/kankan` is not checked again under the lock;
- credentials, a rebuilt snapshot with the same names, or hooks set both globally and inside the checkout, appearing during the questions;
- the final sweep of the state directory is not anchored to directory descriptors;
- the remote probe may let ssh record a new host key or git update a cookie file.

A configured worktree root that contains `<gcd>/kankan` is refused; the default root never does.
