# kankan — agent instructions

- Always update the specification before writing a plan for a new feature. The specification is the set of files in `aispecs/`: the initial pair `initial_spec_functional.md` (what users and agents observe) and `initial_spec_technical.md` (how kankan implements it), which share one section numbering, plus one pair per feature, `<feature>_spec_functional.md` and `<feature>_spec_technical.md`.
- A new feature gets its own pair, with its own numbering and a chapter stating how it changes the initial behaviour (by initial section number); it is planned from its pair. A feature's pair stays its specification after implementation and is never merged into the initial files; its status line says whether it is implemented. Current features: `boardsettings_spec_*` (board settings, model and effort; implemented locally; its status lists the remaining release observation gate), `questions_spec_*` (Q&A cards answered through comments by a dedicated seat; implemented locally; its status lists the outstanding live agents run), `cardinstructions_spec_*` (agent sections in a card's description and the `Instructions` help card; implemented locally; its status lists the outstanding live agents run), `stopall_spec_*` (`kankan stop` without a seat stops every agent and disables autostart, `kankan start` restores them; implemented locally), `takeover_spec_*` (the `--takeover` check and `reconcile --fix` moving stranded cards back to `Backlog`; implemented locally), `destroy_spec_*` (`kankan destroy` deletes kankan's cards, archives the seat lists and removes the local state, to start over; implemented locally), `alerts_spec_*` (problems of kankan's agents that belong to no card posted as comments on an `Alerts` card at the top of the `kankan` list; specified, not implemented), `seat_spec_*` (`kankan seat start` and `kankan seat stop` act on one existing seat, the latter replacing `kankan stop <seat>`; `kankan seat remove [--graceful]` in any state, giving the seat's cards to the board and adjusting autostart; a new Q&A conversation with nothing new is not prompted; implemented locally), `boardreader_spec_*` (one shared reader of the board for every kankan process: each read states how old its data may be, a cache answers when fresh enough, a board-wide read finds new comments; implemented locally; its status lists the outstanding live agents run), `qapool_spec_*` (a pool of Q&A agents of one type routed by their prompt cache: a card stays with its agent while the cache is warm, a new agent opens when every agent is warm on other cards, cold agents are closed after a search; expiry note on answers, warm/cold title prefix; requires the board reader; implemented locally; its status lists the outstanding live agents run), `dialogs_spec_*` (unexpected agent screens and logged-out agents: a seat holding a card on an unrecognized screen gets `Error` with the screen's last lines after a few minutes in any launcher state, unblocked from tmux or with a `keys:` comment; a settled ready screen before the first write; Codex's model retirement notice as a known dialog; a logged-out agent type stops claiming cards, asks for a login and resumes after it; Claude's advance login warning is passed on; specified, not implemented). Proposals not to be implemented until a need is found: `aispecs/proposals/`.
- Kanban backend requirements: `aispecs/kanban_requirements.md`.
- Implementation plans: `aiplans/`. Project knowledge base: `aiknowledge/index.md`, which lists its topic files.
- Python code uses 4-space indentation (PEP 8), overriding the global tabs rule (see `.editorconfig`).
- Runtime code uses the Python standard library only (Python >= 3.10); pytest is a dev dependency.
- Run the full test suite in parallel: `setsid -w .venv/bin/python -m pytest -q -n 16 --dist worksteal` (about 2 min); single files or single tests can run serially. See [developer manual §1](docs/developer-manual.md#1-setup-and-tests).
- Every commit that adds, changes or removes something kankan requires from the board revises `aispecs/kanban_requirements.md` in the same commit: a Trello endpoint call, and also behaviour of the board product outside the API that kankan relies on (for example how its editor stores what users type).
- Increment [kankan/VERSION](kankan/VERSION) in each commit that changes the installed program or its packaging. Tests and documentation outside the package can change independently. See the [version reporting specification](aispecs/version_spec_functional.md).
