# kankan Q&A agent pool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the single Q&A seat becomes a pool of Q&A agents of one type: `<type>-qa` routes every `Q&A` card that needs an agent to the agent holding its warm prompt cache, an available agent, or a new member `<type>-qaN` it opens; members are closed after a search or when their card ends; answers end with the cache expiry note; card titles carry a warm/cold prefix; stop, start and a type change never lose a cut-short answer.

**Architecture:** a new module `kankan/qapool.py` holds the policy: cache expiry (`expiry`), the answer record (`qa-answered.json` under `qa-answered.lock`), offers (`qa_offer` in seat state under `qa-pool.lock`), the routing round, opening and closing members, the stopping mark (`qa-pool.json`), title prefixes (`title-prefixes.json`) and `plain_title`. `QaLauncher` runs as the **router** (`<type>-qa`) or a **member**; the router replaces today's idle claim by the routing round, run every `qa_poll_seconds` in every state. A hidden `kankan statusline` command records Claude's cache expiry. Removing any Q&A seat (`seatremove.complete`) completes its pending answers first, so every removal path keeps cut-short answers.

**Tech Stack:** Python ≥ 3.10, standard library only at runtime; pytest (`setsid -w .venv/bin/python -m pytest -q -n 16 --dist worksteal`); fixtures `kproject`, `fake_trello`, `tests/flow.py`, `tests/helpers.py`, `tests/launcher_helpers.py`, the fake agent in Q&A mode (`tests/fakes/fake_agent.py`), the private tmux server of `tests/test_qa_e2e.py` and `tests/test_seatremove_tmux.py`.

**Spec:** [Q&A pool functional](../aispecs/qapool_spec_functional.md) (F) and [Q&A pool technical](../aispecs/qapool_spec_technical.md) (T). Read both first, with the [questions](../aispecs/questions_spec_technical.md) and [seat](../aispecs/seat_spec_technical.md) technical specifications they change.

**Prerequisite:** the board reader ([plan](2026-11-26-boardreader.md)) is implemented and committed: the routing round reads only through `project.board` (`snapshot`, `new_comments`, `thread`, `card` with their freshness).

**Status:** planned, not started; reviewed by the internal advisor and the Codex advisor (2026-11-26), findings folded in (the answer record's alignment with `qa.first_turn`'s date rule also went into T§5).

## Global Constraints

- 4-space indentation; standard library only in `kankan/`; user-facing texts in `kankan/messages.py` (`QA_CACHE_EXACT`, `QA_CACHE_ESTIMATED`, the refusals naming `<type>-qa`).
- Seat pattern `^[a-z]+-([0-9]+|qa([2-9]|[1-9][0-9]+)?)$` in `refstore._SEAT_RE` and `destroy._KANKAN_REF` (T§2). `seats.is_qa` matches the router and the members; `seats.seat_type` unchanged.
- Lock order (T§4): seat-removal lock → `up.lock` → Q&A lifecycle lock → pool lock → conversation lock → project lock → seat-state lock → answer-record lock → board-cache locks. The pool lock and the answer-record lock are held only to read or rewrite their file: never across a Trello request, a process start or a seat removal. `seatremove.complete` is never called with the lifecycle or pool lock held.
- Only the router registers members, writes offers, writes titles and the prefix record, and closes members. Members never scan `Q&A`.
- The answer record is keyed by card: `delivered` (`description`, `comment`, `attachments` by ID), `answered`, `checked`, `inputs` (ID, kind, date) — never a single `waiting` (T§5 step 3). It is rewritten atomically; `checked` and `inputs` in the same write.
- A turn cut short by a killed agent updates nothing in the answer record; a failed turn counts as delivered.
- The stopping mark is cleared only by `kankan start`, `kankan up`, `kankan agent <type> --qa`, `kankan seat start <type>-qa` (and by a type change once the old pool is removed); a router or member launcher that finds it set refuses to start (`config_error`).
- Members never appear in `seat_cap`, per-type counts, `kankan up` without arguments, `agents_cmd.registered_args`, the stop record or the autostart arguments.
- `qa.replace_seat`, `qa-replacing.json` and the takeover of another seat's conversation by a replacement seat (`_complete_replacement`, `_leftovers`, `_carry_label_causes`, `_check_destination`, `_race`) are removed in Task 11. `qa.take_over` **stays**: `QaLauncher.resume` uses it to take up the seat's own conversation after a launcher restart, which members need too.
- Each task updates the existing tests its change breaks, so the suite is green at the end of every task (listed under **Existing tests** per task).
- Test lifetimes: `prompt_cache.lifetime_minutes` accepts a float (as `idle_ready_minutes` does, e.g. `0.05`), so e2e tests make agents go cold in seconds; the fake agent (`tests/fakes/fake_agent.py`) runs a fake status line that calls `kankan statusline` with a configurable `expires_at`.
- **One commit at the end** (global git rule), `kankan/VERSION` incremented once; revise [`kanban_requirements.md`](../aispecs/kanban_requirements.md) (C11, the C1 assumption on card IDs) in the same commit; push after committing. Tasks end with a green test run, not a commit.

## Review Focus

1. **No answer lost, none repeated** — immediate stop, type change, closing, gone member and router start all complete a cut-short answer once; a turn killed before planning is answered again once; a follow-up arriving during a failed turn is delivered once after a restart. Tasks 3, 4, 8b, 11; F tests 12–14, 18, 19, 24.
2. **Router restart and stop races** — a supervisor restart of the router during a stop never reopens the pool; a stop while a member opens leaves none; a router restart with alive members leaves their conversations alone. Tasks 6, 11; F tests 16, 21, 23.
3. **Routing choice** — reservations, one offer per card, wait-key order, available before new, warm fallback after a failed opening, no opening while `limited` or stopping, closing after a search, an ended card's member reused in the same round. Tasks 8a, 8c; F tests 1, 3, 5, 6, 9, 10, 11, 20, 25.
4. **Gone members** — a launcher between two supervisor restarts is never taken as gone; a `free` member past its startup deadline is; its offer and card are released. Tasks 5, 8c; F test 22.
5. **Title prefixes** — only the recorded prefix is ever removed; a user edit is respected; `plain_title` everywhere a title is used. Task 10; F test 8.
