# kankan destroy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kankan destroy` returns a project to its state before `kankan init`: it deletes the cards of kankan's lists, archives the seat lists and removes kankan's local state, behind a stopped-agents gate and typed phrases.

**Architecture:** a new module `kankan/destroy.py` split into a context that opens without a configuration, a gate, two read-only inventories (board, local), questions and execution; the CLI command `destroy` wires terminal input to it. Small helpers go where their data lives: `trello.closed_cards`, `config.registry_state`/`remove_registry_block`, `seats.running`, `labels.resume_time`.

**Tech Stack:** Python ≥ 3.10, standard library only at runtime; pytest; the fake Trello server in `tests/fakes/fake_trello.py`.

**Spec:** [destroy functional](../aispecs/destroy_spec_functional.md) (F) and [destroy technical](../aispecs/destroy_spec_technical.md) (T). Read both first.

**Status:** planned; reviewed by the internal reviewer and the Codex advisor (2026-11-20), findings folded in.

## Global Constraints

- 4-space indentation; standard library only in `kankan/`; no `datetime.UTC`, `StrEnum`, `tomllib`.
- All user-facing texts in `kankan/messages.py`, in English.
- Phrases, verbatim: `discard uncommitted work`, `destroy <board name>`, `remove local kankan state`. Answers are compared after `strip()`, exactly, case included (F§3.4).
- The board name is never printed by `destroy`, not even in an error; the board URL is printed as `https://trello.com/b/<shortLink>` only, because Trello's `url` ends with a slug of the name (F§3.4).
- Nothing is written, board or disk (lock files included), before every needed phrase was given; a wrong phrase, empty answer, Ctrl-C or EOF → success with `cancelled`, "nothing changed" (F§3.5). The first gate and the inventories never create files.
- Order of destruction: board → worktrees → refs → hook/git config/exclude → state, `log.jsonl` and then `config.json` last (T§4.4).
- Lock files kankan uses are never deleted: `<gcd>/kankan/*.lock`, `seats/*.lock` (liveness `<seat>.lock`, and `<seat>.state.lock`, `<seat>.block.lock`), `attachment-locks/*.lock`, `qa/<conversation>/op.lock` (T§3).
- Branches are never deleted or changed; refs are deleted with `--no-deref`; `~/.config/kankan/` and `~/.cache/kankan/` are never touched; no repository-wide `git worktree prune`.
- **One commit at the end** of the implementation (global git rule for a linear workflow), containing the `kankan/VERSION` increment and the `aispecs/kanban_requirements.md` revision (AGENTS.md). Push after committing. Tasks end with a green test run, not a commit.

## Review Focus

1. **A board renamed or rebound between the question and the lock** — cancel with `needs_action`, zero deletes. Task 5 `test_rename_after_answer_cancels`, `test_rebind_after_answer_cancels`.
2. **Trello timeouts, 429 or 5xx during the inventory** — `needs_action`, never local-only mode. Task 4 `test_transient_error_is_not_local_only`.
3. **A custom `worktree_root` with spaces, a user worktree or a symlink alias under it, a stale unrelated worktree registration** — only kankan's exact registered paths are removed. Task 3 `test_custom_root_user_worktree_kept`, `test_symlink_alias_not_followed`; Task 5 `test_unrelated_stale_registration_kept`.
4. **A clone never initialized, or a `config.json` that is invalid JSON, a JSON array, has malformed `seats`, or no board** — `destroy` still runs (local-only or "nothing to destroy"), never an internal error. Task 2 `test_ctx_open_*`; Task 6 `test_unbound_clone_nothing_to_destroy`, `test_corrupt_config_local_only`.
5. **A second run after a completed run, and a run on a clone holding only a ref or only lock files** — "nothing to destroy" (exit 0) after at most one destructive run, no leftover `log.jsonl`. Task 6 `test_second_run_nothing_to_destroy`, `test_ref_only_clone_twice`.
