# kankan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `kankan`, a stdlib-only Python CLI that lets Claude Code and Codex agents in tmux claim, implement, cross-review and integrate Trello cards on one Git clone, with Git refs as the only source of ownership.

**Architecture:** Ownership and phase live in `refs/agent-cards/*` and `refs/agent-seats/*`, changed only by compare-and-swap or `git update-ref --stdin` transactions. Trello is written after Git ("Git first, then Trello") and a convergence step repairs any lag. A supervisor → launcher → agent process chain per seat runs in tmux; the launcher picks tasks, prepares branches and worktrees, types one-line prompts into the pane and reads signals the agent writes through the CLI.

**Tech Stack:** Python ≥3.10 standard library only (runtime); pytest (dev only); Git ≥2.38; tmux ≥3.2; Trello REST API.

**Spec:** `aispecs/kankan_spec.md` (v1.1) and `aispecs/kanban_requirements.md`, in this repository. Section numbers like §10.3 refer to the spec; "AT n" refers to acceptance test n in spec §18.3.

## Decisions taken in this plan (not in the spec)

- **Repository:** standalone repo `~/coding/kankan`, branch `main`, already created with `aispecs/`, `aiplans/`, `aiknowledge/` and `README.md`. Generated docs (manual, adapter notes) go in `docs/`.
- **Rule conflicts called out (AGENTS-CORE requires it):**
  - AGENTS-CORE limits plan snippets to 5 lines; test steps therefore give the test name plus ≤5 lines of assertions.
  - AGENTS-CORE says "commit only at the end unless needed for agent coordination". Per-task commits are kept: in subagent-driven execution each task is a review gate, which is agent coordination. Push after each commit once the remote exists.
  - AGENTS-CORE says "indent with tabs"; the user overrode it for this project: Python code uses 4-space indentation (PEP 8), configured in `.editorconfig`.
- **Language of user-facing text:** Trello comments, CLI messages and the agent prompt are English (as quoted in the spec), centralized in `kankan/messages.py` so another locale is one file. The user manual is English too.
- **Test-only hooks:** fault injection through `kankan/faults.py` (`faults.point(name)` raises `SimulatedCrash` when `KANKAN_FAULT=<name>`); time through `kankan/clock.py` (`now()`, `monotonic()`), monkeypatched in tests.
- **Comment de-duplication:** every kankan comment ends with the line `` `kankan:<op-id>` ``. For transitions the op-id is the new ref blob's oid, so a convergence retry of the same transition reuses it.
- **Single board read:** `GET /1/boards/{id}` with nested `lists`, `cards`, `labels`, `card_attachments` (§6.3 "one call"). This changes the endpoint mapping of `kanban_requirements.md` B3–B5 (Task 8 revises it).
- **Blob field `from_list`** (addition to the §10.2 example): the list the card was in when the transition was written. Convergence moves a card only from `from_list` to `target_list`; a card found anywhere else was moved by a human (§14.4, §14.6), and convergence never moves it back.
- **Crash-safe multi-ref updates:** with the files ref backend a `git update-ref --stdin` commit is atomic against concurrent writers but not against a crash mid-commit. Writers and consistency readers hold the project lock; `integrate` repairs a half-applied commit from the `Kankan-Card`/`Kankan-Tested` trailers on `main` (Task 19).
- **Idempotent completion:** `done`, `yield`, `block`, `integrate` succeed when rerun after their effect already happened (ref already in the target phase or already deleted with the card in `Done` and its merge on `main`), so a crash or a convergence pass in between never strands the agent.
- **Seat state concurrency:** `<seat>.state.json` is changed only through `update_state(paths, seat, fn)`, which holds `seats/<seat>.state.lock` (flock, never deleted) around read-modify-write. Launcher, agent commands and `stop` all use it.
- **Trello write retries:** reads retry; non-idempotent writes (create list/label, comment) never retry blindly: after a timeout they reread (by name for lists/labels, by marker for comments) and create only if absent. Total retry budget per call under the project lock: 15 s, then `NETWORK_ERROR`; the work is left to the next convergence pass. Rate limiting relies on bounded 429 handling (`Retry-After`) plus a per-process bucket of 90 requests / 10 s; no cross-process throttle.
- **`block` transfer** (§12.4) uses a journal and copies the exact index file instead of re-marking resolved files (Task 20).
- **Hidden internal commands** besides `supervisor`/`launcher`: `kankan tick` (one launcher iteration without an agent: convergence + choice + preparation; used by Phase-1 tests and by the launcher itself).

## Global Constraints

- Runtime imports: standard library only. `pytest` only under `[project.optional-dependencies] dev`.
- Minimum versions: Python 3.10, Git 2.38, tmux 3.2. Installed on the dev server: Python 3.12.3, Git 2.43.0, tmux 3.4, Claude Code 2.1.319, codex-cli 0.167.0. Do not use Python >3.10 syntax (no `except*`, no `tomllib` dependency, no `typing.Self`).
- Stdlib mapping: `fcntl.flock` (fds are non-inheritable by default since 3.4, satisfying §7.3); `ctypes` + `prctl(PR_SET_PDEATHSIG=1)`; `urllib.request` for REST; `http.server` + `threading` for the fake Trello; `subprocess` (argument lists, never `shell=True`) for git/tmux; `/proc/sys/kernel/random/boot_id`; `/proc/<pid>/stat` field 22 for start time, field 6 for session id.
- Ref namespaces: `refs/agent-seats/<seat>`, `refs/agent-cards/<card-id>`. Only `kankan/refstore.py` touches them.
- Validation regexes: card id `^[0-9a-f]{24}$`, shortLink `^[A-Za-z0-9]{8}$`, seat `^[a-z]+-[0-9]+$`. Agent types: `claude`, `codex`.
- Paths: `<gcd>` = `git rev-parse --git-common-dir`; state under `<gcd>/kankan/` (`config.json`, `agents.json`, `project.lock`, `seats/<seat>.lock|.state.json|.proc.json`, `log.jsonl`); worktrees under `~/coding/.kankan/<project>/<seat>` and `.../blocked-<shortLink>` (root configurable); user overrides `~/.config/kankan/agents.json`, `~/.config/kankan/credentials` (mode 600).
- Lock files are never deleted or replaced. JSON state is written to a temp file in the same directory, `fsync`ed, then `os.replace`d.
- Branch name: `YYkankan-<shortLink>` (YY = 2-digit creation year); search pattern `??kankan-<shortLink>`.
- Card phases: `impl`, `implemented`, `review`, `integrated`, `parked`. Card blob schema 1 (§10.2): `schema, phase, card, short, owner, session, implementer, implementer_type, branch, target_list, created, nonce`, plus `merge`, `tested` in `integrated` and `cause` in `parked`.
- Defaults: idle poll 120 s; pane tail 30 lines; per-type seat cap 4; new-conversation command `/new` per type (configurable); prompt `Run the current kankan task (kankan skill).`; idle session timeout: never; main branch `main`.
- Exit codes / statuses (§16.4, verbatim): 0 `success`, 10 `no_work`, 11 `already_claimed`, 12 `ineligible`, 13 `main_moved`, 14 `needs_action`, 15 `on_hold`, 20 `network_error`, 21 `trello_error`, 30 `needs_reconciliation`, 31 `not_owner`, 40 `config_error`, 41 `usage_error`, 50 `internal_error`. JSON envelope: `{"ok","status","message","data"}`.
- tmux session names: agent `ai-<project>-<seat>`, resolve `kankan-resolve-<project>-<shortLink>`, with `<project>` sanitized (Review Focus 1).
- Credentials never appear in logs, comments, blobs, config or output; no Trello text is ever interpolated into a shell command.
- Every commit that adds, changes or removes a Trello endpoint call revises `aispecs/kanban_requirements.md` in the same commit.

## Review Focus

1. **Project names with `.` or `:`** (e.g. `~/coding/studio.ghezzi.net`): tmux rewrites/rejects them in session names. Expect a sanitized name (`[^A-Za-z0-9_-]` → `_`) that still starts with `ai-` and is found by `airesumer.sh discover_panes`. Test in Task 11.
2. **airesumer false positive:** `agent_running` matches a bare word `claude`/`codex` in any descendant's argv. If the supervisor or launcher argv contains the bare type, a dead agent looks alive and airesumer types `resume` into the launcher's pane. Expect internal commands to pass the type as `--type=claude` (the `=` defeats the `(^|[ /])` anchor). Test in Task 13.
3. **Messy `.properties` files:** `key=value`, `key: value`, `key value`, CRLF line endings, `\` continuations, `!` comments, unicode escapes, no trailing newline. Expect byte-identical preservation of everything except kankan's own values. Test in Task 3.
4. **Symlinked `~/coding`** or worktree root: expect the trust-window check to compare `realpath(worktree)` against `realpath(root)`, so auto-answer still works; a worktree outside the root is never auto-answered. Test in Task 13.
5. **Card deleted or archived on Trello while its ref is `impl`/`review` and the owner seat is working:** expect the §14.6 path (WIP + `yield` request, ref → `parked` with cause `user_deleted`/`user_archived`, no Trello write), `task` answering `ineligible`, and `reconcile` listing the ref. Test in Task 24.

### Task 20: `block` and `resolve`

**Files:** Modify `kankan/integrate.py`, `kankan/agentcmds.py`, `kankan/cli.py`; Test `tests/test_block_resolve.py`.

**Interfaces:** `block(ctx, reason)`. With a merge in progress, a journal-driven transfer, each step idempotent and resumable by `block` rerun or by the launcher at startup (`block_journal` in seat state, snapshot dir `<gcd>/kankan/blocks/<short>/`):
  1. `snapshot`: record `HEAD`, `MERGE_HEAD`, `MERGE_MSG`, `MERGE_MODE`, the `main` hash merged, a copy of the worktree's index file, and every path from `git status --porcelain=v1 -z --untracked-files=all` (staged, unstaged, unmerged, deleted, untracked) copied with `shutil.copy2`/symlinks preserved, plus a list of deleted paths; record a digest = `git status --porcelain=v2 -z` + `git diff --binary` + `git diff --cached --binary` hashes.
