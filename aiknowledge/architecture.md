# Architecture

## Modules and branches

- Module map: `refstore` (only module touching `refs/agent-*`; `destroy` deletes through `RefStore.delete_exact`), `trello` (only module talking to Trello), `config`/`properties`/`auditlog`, `seats`/`seatstate`/`procutil`, `cards` (transitions, convergence), `workflow` (choice, claims, `tick`), `integrate` (sync, verify, integrate, review done, block, resolve), `agentcmds` (agent commands), `launcher`/`supervisor`/`forward`/`tmux`/`adapters`, `agents_cmd` (agent, up, autostart), `attachments` (task inputs, download cache; called by `task` outside the lock), `diag` (status, claims, reconcile, admin), `doctor` (checks, fixes, preflight), `destroy` (`kankan destroy`: inventory, phrases, destruction), `init`, `cli`.
- The agents integrate into `cfg.integration_branch` (default `kankan-agents`; old configs with `main_branch` are read as an alias); `cfg.user_branch` is the user's. Only `integrate` moves/pushes the integration branch (`pre-push` hook + `KANKAN_PUSH=1`); user work enters through merge-request cards (`integrate.merge_request`, SHA pinned at request time). The JSON key `main`, `push_main` and `main_moved` keep their names for compatibility.
- The default agent adapters are in `kankan/adapters_default.json`; the screens they were built from are in `tests/fixtures/screens/`, described in [`docs/adapter-notes.md`](../docs/adapter-notes.md).

## Processes, seats and code identity

- Seat removal (`kankan/seatremove.py`): `SeatConfig.removing` (`graceful`/`immediate`) is persisted in `config.json` and read fresh by other processes (the claim recheck in `workflow.tick` and `qa.claim` reload the config under the lock). A seat being removed: takes only its own work, is never picked by `seats._candidates`, never counted by `live_counts`/`registered_args`/`_args_from_seats`, and its lists leave `required_lists` (otherwise every other seat's `check_lists` stops with `CONFIG_ERROR` while a completion has archived some of them). `seatremove.complete` is serialized by `seats/<seat>.remove.lock` and deletes the config entry last; it removes the seat worktree (force, after `merge --abort`) before any card moves, so no card branch stays checked out. Lock files are never deleted. `agents_cmd.resume_removals` (called first by `up`, and by bare `up`/`start` without record) is the only code restarting (env `KANKAN_SEAT_EXISTING_ONLY=1`: the launcher never re-creates a seat) or completing such seats. A crash between a card move and its comment loses the comment (no journal, by decision).
- `cards.implemented_destination(cfg, implementer)` is the single destination of a card going back to review (`done`, review `yield`, HOLD rollback, `resolve --done`, removal): another seat's `Implemented` (same type first, by seat number) when the implementer's seat is gone or being removed, else `parked` to `Backlog` with cause `seat_removed`. Review eligibility reads `implementer_type` from the ref, so a card in another seat's list is still reviewed only by the other type.
- Codex 0.167 runs shell commands through a shared `codex app-server --managed-daemon`: they get the daemon's environment (login PATH, no `KANKAN_*`). Agent commands therefore fall back to `<worktree git dir>/kankan-agent.json` (written by the launcher), and `kankan` must be on the login PATH.
- `build.code_id()` hashes the kankan package; the launcher stores it in the seat file with the version and package directory (`build.identity()`), and agent commands refuse to run with different code (editable installs make this likely while developing kankan).
- kankan starts its own processes only through `build.command()` (`python -c` bootstrap dropping `""` from `sys.path`), never `python -m kankan`: the supervisor, the launcher, the agents' wrapper and the autostart unit run in the repository or a seat worktree, and in kankan's own repository `-m` imports the checkout's `kankan/` instead of the installation. `agents_cmd.UNIT_UP` reads the unit's `ExecStart` in both the current and the pre-0.1.7 `-m kankan up` form.
- `doctor` checks and fixes the installation and project; its offline subset is the `up`/`agent` preflight. The launcher and `agent` put `<gcd>/kankan/bin` (only a `kankan` wrapper running `sys.executable -m kankan`) first on the agents' `PATH` (`agents_cmd.agent_path`): never the interpreter's own directory, which would shadow the project's python/pip.
- `workflow.tick(project, lease)` is one launcher iteration without the agent (convergence, choice, preparation); the hidden `kankan tick --seat <s>` runs it for debugging.
- Seat state (`<gcd>/kankan/seats/<seat>.state.json`) is changed only through `seatstate.update_state`.
- The launcher shares the pane's terminal with the agent: it never prints while the agent runs; events go to `<gcd>/kankan/log.jsonl`.
- The launcher checks its seat lease every poll interval and exits when `seat recover` revoked it.
- `seat recover --kill` terminates only the recorded processes (pid + start time); a whole session is terminated only when it is the recorded supervisor-led pane session.
- Seat recovery terminates the processes of the recorded pane session only when that session was created by a kankan supervisor (`KANKAN_SUPERVISOR_PID` equals the session id) and the session leader's start time still matches; otherwise it kills nothing.
- `Launcher.start` clears a stale `stop_requested` before publishing `starting` (a stop seen after `starting` must survive); a launcher restarted by its supervisor still clears it, so `kankan stop --graceful` re-asserts the request while it waits.
- `kankan stop --graceful` and `kankan seat stop <seat>` wait for an agent to finish its task, which never happens when its commands are refused for a code mismatch, so both refuse first (`stopall.refuse_other_code`, `usage_error`, nothing changed): for each alive seat, the `code` in its `kankan-agent.json` counts only when the file's `session` equals the seat ref's `meta["session"]` (no file, an unreadable one, another session or no ref give no verdict and never refuse), and differs from `build.identity()["code"]`. The immediate `kankan stop` (`seat recover --kill` on every seat) needs no cooperation from the running code, so it stops launchers of any version.

## Cards

- Card refs carry `from_list` only while a Trello move is unconfirmed: after a verified move `cards.confirm_move` rewrites the ref without it, so convergence moves a card only from its recorded source and never replays a move over a later human move.
- Transitions of held cards (`impl`/`review`) by a seat require the card to be open and in its expected list; only the user-move parking (`cause` `user_*`) is exempt. `integrate` and review `done` apply the same rule and re-check seat ownership and task identity under the project lock.

## Attachments

- `attachments` (spec §13.3) is the policy of card attachments as task inputs; `agentcmds.task` calls `attachments.for_task`. Uploads by `notify.input_members` (board members minus kankan's account) are downloaded to `<gcd>/kankan/attachments/<shortLink>/<att-id>/<sanitized fileName>`. Every change inside a card's directory happens under the per-card attachment lock (`<gcd>/kankan/attachment-locks/<shortLink>.lock`, ordered after the project lock); `task` never takes the project lock. `cards.delete_integrated_ref` is the only way an integrated ref is deleted in `Done`. `attachments.discard` never waits (timeout 0) and never follows symlinks; a `task` holding the lock deletes the directory itself when its `still_held` check returns `Hold.GONE` (ref deleted), and never for `Hold.OTHER` (another owner or phase, or an unreadable ref: the copies may be another seat's). A ref deleted after the `task`'s final check but before it releases the lock leaves the directory behind (`discard` found the lock busy); `reconcile --fix` removes it. Names are sanitized to at most 255 UTF-8 bytes; the attachment directories are created with mode 0700; once a download hop leaves the API origin, no later hop carries the credential.
