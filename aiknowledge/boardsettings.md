# Board settings

- `boardconfig` evaluates immutable Trello read envelopes without I/O or local time. `boardsettings` serializes evaluation under the project lock, persists effective values and action intents before feedback, and reserves the shared settings-list poll. Schema/input fingerprints and revisions keep feedback and probe results tied to the edit and CLI version that produced them. Missing server/activity dates defer evaluation; an unavailable settings list preserves values.
- Lock order: settings construction lock → short project lock; feedback writer lock → project lock for individual feedback actions. Catalog/probe preparation and terminal seed questions run outside project locks. User seed and cache writes re-read under their own user-level locks and atomically replace files. Ordered model mappings use `sort_keys=False`. `seed` is the adapter JSON key; no adapter ships one.
- `modelcheck` polls isolated child processes and caches results per type/version/model/effort. A timeout is unverified and carries only a retry deadline. Read-only lookup starts no child and writes nothing. `model_catalog` prepares versioned catalogs explicitly; evaluation only reads them.
- Workflow preparation pins the pair at claim and defers publishing a task ID until activation. Activation checks seat/ref/list/HOLD/stop/binding. A planned launcher restart retains the seat lease and work, uses individual PID signals, preserves adapter-listed shared daemons, and starts the pinned pair. The launcher is a subreaper; adopted processes are reaped by PID, excluding all Popen-owned children, so model-check exit codes remain available. Running selection is published at readiness.
- Shared CLI-version and catalog observations carry ordering tokens, so a late completion cannot restore an older selection or check result. Timed-out children remain owned by their Popen objects and are polled after cancellation; no timeout path waits indefinitely for a child. Probe directories ignore inherited TMPDIR and are validated against repository/instruction ancestors.
- The launcher keeps a claimed but not yet activated task on `Launcher.prepared` (with its pinned pair) until `workflow.activate_task` succeeds; it never ticks meanwhile. Activation and the pre-prompt recheck (`refresh_task`) follow tick error handling: transient errors retry at `poll_seconds`, `NOT_OWNER` exits normally, `CONFIG_ERROR` stops. A stop before the prompt gives a fresh claim back (`workflow.release_unsent`); resumed or dirty work stays held.
- Per-second launcher work never ends a task on errors: `Launcher.refresh_settings` logs a config/settings error once and sets `stop_after_task` for `CONFIG_ERROR`. `boardsettings.poll` pre-checks the shared reservation without the project lock; unchanged cached check results are re-recorded at most once per settings poll; `procutil.reap_adopted` peeks with `waitid(WNOWAIT)` before scanning `/proc`.
- A seed that the Codex catalog no longer lists is moved to `Adapter.stale_seeds` and counts as missing (the seed question replaces it); only explicit `models` overrides make an invalid seed a `config_error`. `unavailable` entries in `<seat>.proc.json` always carry a start time; entries without one are never treated as alive.
