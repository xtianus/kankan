# Q&A (questions)

- The Q&A seat `<type>-qa` (`SeatConfig.role == "qa"`, no lists, own worktree; seat names match `^[a-z]+-([0-9]+|qa)$`, at most one registered) serves the `Q&A` list (`cfg.qa_list`, optional: a missing or archived list stops only the Q&A seat). `launcher.main` builds a `QaLauncher` (`kankan/qa_launcher.py`) for a seat ending in `-qa`; it overrides the base launcher's hooks and adds the state `qa_waiting` (follow-up polling every `qa_poll_seconds`, default 30; each poll there also reads the `Q&A` list). Work seats never take `Q&A` cards and count only `work` seats.
- `kankan/qa.py` is the conversation policy (record, claim, end, inputs and `new`, turns, handoff transition, seat replacement); `kankan/qa_answer.py` posts (chunking, pending operation, `answer`, `handoff`, commit check). Q&A transitions use `refstore` transactions that verify the seat ref, not `cards.transition`. Card ref phase `qa` carries `conversation` and `covered`; a handoff parks the card with `cause: handoff`, `pos: bottom`, `handoff` (summary comment IDs), copied into the `impl` ref by the implementation claim.
- Files: `<gcd>/kankan/qa.json` (cards that were Q&A cards, exempt from `reconcile`'s `done_without_merge`; an implementation claim removes the entry, `reconcile --fix` those of archived or deleted cards, read before the project lock), `<gcd>/kankan/qa/<conversation>/` with `op.lock`, `turn.json` (turn token, delivered inputs, first-turn context, run ID) and `pending.json` (a chunked answer or handoff being posted). The directory is deleted at the end of a conversation that was not handed off, by `cards.delete_integrated_ref`, by a new claim of a card whose parked ref names an older conversation, or by `reconcile --fix`.
- Lock order: `up.lock` (held by `kankan up` while it registers the Q&A seat) → Q&A lifecycle lock (`<gcd>/kankan/qa-lifecycle.lock`: seat replacements and `seat remove <type>-qa`) → conversation lock (`qa/<conversation>/op.lock`; `qa.LockBusy` when not taken in time) → project lock → seat-state lock. `fail` in a Q&A task runs its validation, card read, label, comment and signal under the conversation lock, so no turn starts meanwhile. A Q&A hold of the project lock contains at most one card read, one Git transaction and one move with its verification read; chunks are posted, attachments downloaded and the agent awaited without it. A work seat's implementation claim holds the project lock through its board read, card read, move, verification read, claim comment and HOLD recheck (unchanged by the feature).
- Turns: every prompt gets a turn token saved in `turn.json` and the seat task before the pane write; `answer`, `handoff` and (optionally, `--turn`) `fail` carry it, signals carry it, and `QaLauncher.take_signal` drops a signal of another turn. A restart (launcher start, agent restart for a new pair, seat replacement) writes `QA_RESTART` only when the conversation has uncovered inputs or no `covered` yet; otherwise it goes to `qa_waiting` silently and the next delivery uses `QA_RESTART_FOLLOWUP`. A turn ending without a signal, and every delivery or typed turn, first tries the conversation lock without waiting and completes the turn's `pending.json` (`QaLauncher.settle_pending`: a completed answer is no `Error`; a busy lock means the command is still posting). A pending operation of an older turn is completed (without a signal), never dropped. `task`, `fail` and `note` read the card again and give `not_owner` once it left `Q&A`, is archived or on `HOLD`, before the launcher's poll deletes the ref. `new` after a conversation restart is decided by Trello dates, never the local clock. The commit check counts only commit-creating `HEAD` reflog entries (commit, merge, cherry-pick, revert, rebase, am, pull) since the claim.
- `HOLD` on a handed-off card still in `Q&A` with its move outstanding cancels the handoff: convergence (`cards._cancel_handoff_move`) drops `from_list`/`pos`, sets `target_list` to `Q&A` and does not move; the card is taken again as a new conversation once `HOLD` is removed.
- Accepted window: a crash after the handoff move but before `confirm_move`, followed by the user dragging the card back into `Q&A` before any convergence, moves it to `Backlog` once more (the same window as `cards.transition`); a second drag sticks.
- Accepted delay: an idle Q&A launcher does not claim while a CLI-version or catalog check of its type runs (`QaLauncher.idle` checks again at the next step); the check does not block the step loop, so a claim waits for its completion only.
- Seat replacement (`qa.replace_seat`, run by `agent --qa`, `up qa=<type>` and, completing only, by the new seat's launcher): (1) the old seat must be `dead` or `free` with no survivor; (2) one configuration write swaps the old entry for the new one, so at most one Q&A seat is ever registered and `seats.acquire_qa` refuses the old name (an old supervisor stops on `FATAL_EXIT`); it also writes the replacement record `<gcd>/kankan/qa-replacing.json` (old, new); the later stages are identified from the `qa` ref's owner, the old seat ref and, while the record names the pair, the old worktree and seat files (a plain `seat remove` is no replacement): (3) the `qa` ref is rewritten with the new owner, verifying the old ref value and the old seat ref; (4) the old seat ref is deleted; (5) the old seat's label causes for the moved cards go to the new seat, the old worktree (if clean), seat files and the record are removed. A record whose new seat is neither registered nor starting is dropped (`qa.drop_stale_record`, also by `seat remove <type>-qa`). `task` deletes the files of an ended conversation only under the project lock (tried without waiting) and only while no newer task or conversation of the card exists. Replacements hold the lifecycle lock and every stage re-checks that its destination is the registered Q&A seat. With no Q&A seat registered, a starting seat registers itself and completes the leftovers of another one; `reconcile` reports `qa_owner_unregistered` for a `qa` ref whose owner is not registered.
- Shared Q&A helpers, one definition each: `qa.QA_MARKER` (the answer/handoff chunk marker, read by `qa.first_turn` and by `task`'s thread and handoff summary), `qa.handed_off` (the handoff transition happened; `qa_answer` also passes the posted summary IDs, the launcher does not know them), `worktrees.reflog_subjects` (the `HEAD` reflog, used by `reflog_length` and the commit check), and the ownership helpers `qa.ours`, `qa.check_seat`, `qa.drop_orphan`, `cards.parse_refs`, used across modules.
- `boardconfig.roles(paths)` (the active roles: seeds, preflight, setting cards created, doctor checks and probes) adds `questions` only while a `qa` seat is registered, and logs an unreadable configuration (`roles_config_unreadable`); the evaluation always uses `adapters.ROLES`, so the `questions` card never becomes an unknown setting; a launcher compares only its `own_roles()`. `up qa=<type>` and `agent --qa` check the `Q&A` list, replace a Q&A seat of another type and register `<type>-qa` (`agents_cmd._register_qa_seat`) before the `questions` seed preflight, so a start refused for a missing seed leaves the seat registered (status `free`) and `init`/`doctor` then ask for the seed and create the `questions` card.
- Tests: `tests/test_qa*.py`; `tests/test_qa_e2e.py` runs the Q&A seat with work seats end to end and the independence test (fake Trello `delay` fault, project-lock holds measured by polling the lock file). Fake agent steps substitute `{turn}` and `{file}`. Launcher tests that assert nothing happened wait for poll cycles counted in the fake Trello request log (`wait_card_polls`: comment reads of the active card; `wait_board_polls`: idle board reads), not for fixed times; only states without any Trello poll (`limited`, an ended conversation) keep a short sleep.
