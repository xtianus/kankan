# Q&A (questions)

- The Q&A pool (`kankan/qapool.py`): the router `<type>-qa` and the members `<type>-qa2`, `<type>-qa3`, … (`SeatConfig.role == "qa"`, no lists, own worktree; seat names match `^[a-z]+-([0-9]+|qa([2-9]|[1-9][0-9]+)?)$`; `Config.qa_seat()` is the router only, `qapool.members(cfg)` the members; all of one type) serve the `Q&A` list (`cfg.qa_list`, optional: a missing or archived list stops only the Q&A seats). `launcher.main` builds a `QaLauncher` for any `seats.is_qa` seat; it adds the state `qa_waiting` (follow-up polling every `qa_poll_seconds`, default 30). Work seats never take `Q&A` cards and count only `work` seats; members never appear in `seat_cap`, `registered_args`, the stop record or the autostart arguments.
- `kankan/qa.py` is the conversation policy (record, claim, end, inputs and `new`, turns, handoff transition); `kankan/qa_answer.py` posts (chunking, pending operation, `answer`, `handoff`, commit check). Q&A transitions use `refstore` transactions that verify the seat ref, not `cards.transition`. Card ref phase `qa` carries `conversation` and `covered`; a handoff parks the card with `cause: handoff`, `pos: bottom`, `handoff` (summary comment IDs), copied into the `impl` ref by the implementation claim.
- Files: `<gcd>/kankan/qa.json` (cards that were Q&A cards, exempt from `reconcile`'s `done_without_merge`; an implementation claim removes the entry, `reconcile --fix` those of archived or deleted cards, read before the project lock), `<gcd>/kankan/qa/<conversation>/` with `op.lock`, `turn.json` (turn token, delivered inputs, first-turn context, run ID) and `pending.json` (a chunked answer or handoff being posted). The directory is deleted at the end of a conversation that was not handed off, by `cards.delete_integrated_ref`, by a new claim of a card whose parked ref names an older conversation, or by `reconcile --fix`. Those deletions only try the conversation lock (`discard_conversation`, timeout 0), so a command holding it at that moment keeps the directory alive: every command takes the lock through `qa.card_conversation_lock`, which runs `drop_orphan` on release (no ref names the conversation any more → directory deleted). Without it the directory stayed until `reconcile --fix` (seen as a flaky `test_qa_e2e` under parallel load).
- Lock order: seat-removal lock → `up.lock` → Q&A lifecycle lock (`qa-lifecycle.lock`: the routing choice, the stopping mark, the router's start) → pool lock (`qa-pool.lock`: offers, held only to read or write) → conversation lock (`qa/<conversation>/op.lock`; `qa.LockBusy` when not taken in time) → project lock → seat-state lock → answer-record lock (`qa-answered.lock`) → board-cache locks. `seatremove.complete` is never called with the lifecycle or pool lock held; the router removes gone members in a background `kankan pool-remove <seat>` process. `fail` in a Q&A task runs its validation, card read, label, comment and signal under the conversation lock, so no turn starts meanwhile. A Q&A hold of the project lock contains at most one card read, one Git transaction and one move with its verification read; chunks are posted, attachments downloaded and the agent awaited without it.
- Turns: every prompt gets a turn token saved in `turn.json` and the seat task before the pane write; `answer`, `handoff` and (optionally, `--turn`) `fail` carry it, signals carry it, and `QaLauncher.take_signal` drops a signal of another turn. A restart (launcher start, agent restart for a new pair, seat replacement) writes `QA_RESTART` only when the conversation has uncovered inputs or no `covered` yet; otherwise it goes to `qa_waiting` silently and the next delivery uses `QA_RESTART_FOLLOWUP`. A turn ending without a signal, and every delivery or typed turn, first tries the conversation lock without waiting and completes the turn's `pending.json` (`QaLauncher.settle_pending`: a completed answer is no `Error`; a busy lock means the command is still posting). A pending operation of an older turn is completed (without a signal), never dropped. `task`, `fail` and `note` read the card again and give `not_owner` once it left `Q&A`, is archived or on `HOLD`, before the launcher's poll deletes the ref. `new` after a conversation restart is decided by Trello dates, never the local clock. The commit check counts only commit-creating `HEAD` reflog entries (commit, merge, cherry-pick, revert, rebase, am, pull) since the claim.
- `HOLD` on a handed-off card still in `Q&A` with its move outstanding cancels the handoff: convergence (`cards._cancel_handoff_move`) drops `from_list`/`pos`, sets `target_list` to `Q&A` and does not move; the card is taken again as a new conversation once `HOLD` is removed.
- Accepted window: a crash after the handoff move but before `confirm_move`, followed by the user dragging the card back into `Q&A` before any convergence, moves it to `Backlog` once more (the same window as `cards.transition`); a second drag sticks.
- Accepted delay: an idle Q&A launcher does not claim while a CLI-version or catalog check of its type runs (`QaLauncher.idle` checks again at the next step); the check does not block the step loop, so a claim waits for its completion only.
- Routing (`qapool.Router`, run by the router every `qa_poll_seconds` once its own agent is ready, in every state): reads through the board reader, updates the answer record (`qa-answered.json`: per card `delivered`, `answered`, `checked`, `inputs`; comments by date, attachments by ID), builds a `SeatView` per pool seat (warm from `qapool.expiry`: an exact reading `<seat>.cache.json` written by `kankan statusline` for the current agent process, else `turn_ended_at` + `prompt_cache.lifetime_minutes`), runs the pure `qapool.choose` under the lifecycle and pool locks (reservations for holders with listed inputs, wait-key order, lowest available seat, new member, warm fallback after a failed opening; nothing while stopping, no opening while limited; closing after a search, ended-card members, gone members), writes offers (`qa_offer` in the seat state) and registers members there, starts them after the locks (`agents_cmd.start_member`), marks closings (`removing: graceful`) and finally writes the title prefixes (`title-prefixes.json`, only the prefix kankan wrote). A seat takes an offer between turns (`QaLauncher.take_offer`): its old conversation ends (`qa.end`, the card stays in `Q&A`) and it claims the offered card. Members never scan `Q&A`.
- Start, stop and type change: the stopping mark `qa-pool.json` makes `acquire_qa` refuse every Q&A launcher (`seats.POOL_REFUSED`: the launcher exits 0, so its supervisor ends) until a start command clears it. The router's start (`qapool.router_start`) completes its own pending answers without a signal (`complete_pending(admin=True)`), ends its own conversations, ends conversations of unregistered Q&A seats, drops a legacy `qa-replacing.json`, removes members whose launcher is gone and clears the prefixes; members still running keep their cards. `kankan stop` marks members for graceful removal or kills and removes them; a type change (`qapool.change_type`, from `up qa=<other>` and `agent <other> --qa`) kills and removes the old pool, members first, then registers the new router. Removing any Q&A seat completes its pending answers first with an admin lease (`seats.occupy_admin`, no pane recorded).
- Shared Q&A helpers, one definition each: `qa.QA_MARKER` (the answer/handoff chunk marker, read by `qa.first_turn` and by `task`'s thread and handoff summary), `qa.handed_off` (the handoff transition happened; `qa_answer` also passes the posted summary IDs, the launcher does not know them), `worktrees.reflog_subjects` (the `HEAD` reflog, used by `reflog_length` and the commit check), and the ownership helpers `qa.ours`, `qa.check_seat`, `qa.drop_orphan`, `cards.parse_refs`, used across modules.
- `boardconfig.roles(paths)` (the active roles: seeds, preflight, setting cards created, doctor checks and probes) adds `questions` only while a `qa` seat is registered, and logs an unreadable configuration (`roles_config_unreadable`); the evaluation always uses `adapters.ROLES`, so the `questions` card never becomes an unknown setting; a launcher compares only its `own_roles()`. `up qa=<type>` and `agent --qa` check the `Q&A` list, remove a Q&A pool of another type and register `<type>-qa` (`agents_cmd._register_qa_seat`) before the `questions` seed preflight, so a start refused for a missing seed leaves the seat registered (status `free`) and `init`/`doctor` then ask for the seed and create the `questions` card.
- Tests: `tests/test_qa*.py`; `tests/test_qa_e2e.py` runs the Q&A seat with work seats end to end and the independence test (fake Trello `delay` fault, project-lock holds measured by polling the lock file). Fake agent steps substitute `{turn}` and `{file}`. Launcher tests that assert nothing happened wait for poll cycles counted in the fake Trello request log (`wait_card_polls`: comment reads of the active card; `wait_board_polls`: idle board reads), not for fixed times; only states without any Trello poll (`limited`, an ended conversation) keep a short sleep.
- A new conversation on a card whose latest kankan answer is complete (no `k/n` prefix, or `n/n`; `qa.CHUNK_PREFIX`) and with nothing new since is started silently (`QaLauncher.start_silently`): `qa.record_covered` writes the old thread as `covered` in the ref (as an answer would), then `wait_after_restart`; the agent's previous conversation is cleared now or before the next follow-up (`clear_before_followup`), since follow-ups are pasted without a clear. A Q&A seat being removed gracefully exits from `idle`/`qa_waiting` once no answer is pending (`removal_drained`); a pending answer is completed by the take-up first.
